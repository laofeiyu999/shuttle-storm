## 3. 踩过的坑（重要）

- `git add -A` 在 `.gitignore` 未覆盖新视频时会**把 250MB 文件一起提交**，push 被 GitHub pre-receive 拒绝（`GH001: Large files detected`）。第一次就因为把删除 ponytail 的改动和未忽略的大视频混在一个 `git add -A` 里，导致整次 push 失败并回滚重做。
- 处置流程：`git reset --soft HEAD~1` → `git reset` 清空索引 → 只 `git add` 目标文件 → 先把大文件写进 `.gitignore` 再提交。
- 提交大文件时 push 会跑很久，`run_code` 里 120s 会被判超时（命令其实还在跑）。用 `ops_bash({run_in_background:true})` 起后台任务，再用 `job_output` 取结果，是本机唯一稳妥的方式。
- 这批文件名里带**零宽空格（U+200B）**，手抄路径一定会错。一律用 Node `fs.readdirSync` 读真实文件名再拼命令或写 `.gitignore`。
- `curl https://github.com` 在本机会超时返回 000，但 git push 走配置的代理可以成功，不要用 curl 结果判断能不能推。
