## 0. 直接回答那个说法

> 「飞羽青春弹道的物理层没有在客户端，找不到；弹道带点物理特性、有重力影响；有个 bridge 桥接层代码，在服务端。」

| 说法 | 判定 | 准确表述 |
|---|---|---|
| 物理层不在客户端 | ❌ **错** | 物理层确实**不在 Python 层**，但它在**原生 C# 层**，客户端有一份、服务端也有一份（双端同源）。客户端单机走 `StepFrame()`→`Simulate()`（`game.py:518`、`scene.py:197-211`），回放/观战模式直接调 `m_Scene.Simulate()`（`game.py:547`、`game.py:568`）。 |

### 为什么「找不到」——这是本仓库最硬的一条结论

真正的曲线几何代码**不在** `Game_dll.dll` 里，而在 `Assembly-CSharp` 里，而 **`Assembly-CSharp` 不在工作区**：

- `Game_dll.dll` 的 Assembly 名是 `Game`，是**热更程序集**，它的引用列表第 2 项就是 `Assembly-CSharp, Version=0.0.0.0`（共 32 个引用程序集，除 mscorlib / System / System.Core 外全是 Unity 与第三方库）。
- 反射解析实测：`GetTypes()` 抛出 `ReflectionTypeLoadException`，异常类型表 4215 项里只有 **3429** 项能成功解析，失败的全是外部程序集类型。逐 token（`ManifestModule.ResolveType(0x02000000+i)`，i=1..4300）解析结果同样是 3429 个。
- 按类型名匹配 `CurveShape|ICurveShapeData` → **命中 0 个**。`NormalCurveShapeData` / `ParabolaDownCurveShapeData` / `TurnAroundCurveShapeData` / `FallingCurveShapeData` / `NormalFakeDropCurveShapeData` / `ICurveShapeData` / `CurveShapeBase` / `CurveShapeDataBase` **全部解析不出来**。
- 反向证据：`M2A5.NetPyBridge` 的字段 `m_CurveShapeSelector`，反射打印出的字段类型 **FullName 为空字符串**（`$_.FieldType.FullName` 拿不到）—— 因为该类型定义在缺失的 `Assembly-CSharp` 里。这是「几何类不在热更 DLL」的直接物证。
- 工作区里也没有任何 `*.pyd`，没有 `phys.py` / `C_data.py`。`bridge.py:15` 的 `import debug, phys, C_data` 在这个仓库里必然 `ImportError`。

所以：**算法只存在于没被 dump 出来的 `Assembly-CSharp`（或它的 il2cpp 版本）里。** 任何声称从本仓库反编译出曲线几何的，都只能是推断，不可能是抄录。

## 1. 三层结构（谁在什么时候算）

```
① 配置表  fls_py\base\data\curve\*.py        ← 纯数据，import 时 Register2OS* 灌进原生
        ↓
② Python 逻辑层  battlelogic / clientlogic / prediction
   · 选哪条形状（hitaction → DoChooseCurve）
   · 算落点（CalcDropPos 家族，纯 Python）
   · 建曲线（m_Phys.CreateCurve 一句，几何在原生里）
   · 收消息、预判过网、假落点回拉、显示平滑
        ↓
③ 原生层  phys.Scene().CreateCurve(...)  /  CreateCurveData.GetPointList() / GetPointBySecond(t)
   ← 球的位置由 m_Phys.Simulate(0.04) 每帧驱动，Python 只 GetMovedControllers() 取结果
```

Python 侧**一句几何公式都没有**。最接近的是这三处，且都不是轨迹积分：

1. `battlelogic\badminton\badminton.py:425-516` —— **落点**计算（X/Z 百分比 + 随机扰动），纯 Python，可 1:1 复刻。
2. `clientlogic\prejudgecurve.py:55-65` —— **过网判定**插值（连网线求交），可 1:1 复刻。
3. `clientlogic\badmintonsmoothmove.py:13-49` —— **显示平滑**（47 帧 Lerp 收敛），可 1:1 复刻。

| `v` 跳号剖面 | 161 条（末 `v` 可达 230，而点数只有 159） |

三条可从数据本身证实的事实：

1. **这是「距离-时间」表，不是「位置」表**：`s` 逐点递增、`v` 是帧号，`s(n)/0.016` 就是瞬时速度。原表按 `timeGap = 0.016` 采样。
2. **有空气阻力**：逐帧位移单调递减（例 h=100/a=20：前 6 帧 0.62 / 0.67 / 0.67 / 0.66 / 0.62 / 0.58 m，末段 Δ=0.01~0.03 m）。线性阻力 `ln v ~ t` 与二次阻力 `1/v ~ t` 的 R² 打平（0.9315 vs 0.9320，各有胜出），说明它是**手工标定的经验剖面**，不能反推唯一物理模型。
3. **原点被抽稀过**：`v` 出现跳号（h=10/a=0 末尾 `v` = 155, 157, 159, 161, 164 但只有 159 个点），说明配置生成阶段按"距离变化阈值"删过点，`v` 保留的是抽稀前的原始帧号。

用途：这套数据在 `fls_curve.py` 里只作为**只读参考层** `TimeProfile`（`row()` / `ref()` / `ref_time()`，`DIST_SCALE = 100.0` 米→cm），**不拿它反推轨迹**。

3. **`IntegrateCurve` / `GetCurvePoint` 的签名** —— **已反编译**：`IntegrateCurve` 载入器@`0xDD5EC`（伪代码见反编译文档第五节）：入参 `(Curve*, pointList, paramA, paramB)`，点表 `(fff)` 三元组按 `(x/100, y/100, z×0.04)` 灌入（SECOND_SCALE=100@.rodata 0x625DE4、STEP=0.04@0x625DE8），末段由首点反推初速存 `vel@self+0xAC`。GetPointBySecond 族查询@`0xCF1A4`；`GetPointList`@`0xD26C0`、`GetDropPos`@`0xD1870` 等 phys 57 方法地址全表见 `phys_funcs.json`。已落地为 `CurveData.GetInitVelocity()` 的 `[F]` 锚点（⚠ 对本库绝对 3D 点列直接调用无物理意义 —— 实测输出只随起点位置变化，与曲线形状无关，物理初速仍以 `solve_by_angle` 解为准）。
