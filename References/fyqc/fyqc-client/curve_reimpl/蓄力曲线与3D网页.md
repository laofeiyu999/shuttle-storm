1. **`fls_py` 里没有弹道积分代码。** 球路的几何计算跑在原生模块 `phys`（C# / il2cpp，见 `hotfix_dll/Game_dll.dll`），Python 侧只有三层：配置表 → 调用封装 → bridge 桥。仓库里没有 `*.pyd`，`phys` / `C_data` 两个模块根本不存在。

## 2. 蓄力曲线簇（核心）

### 2.1 需求与设计边界

用**一个蓄力值 `charge ∈ [0,1]`** 统一驱动三个击球键的球路，并做成可交互 3D 演示：

- 小球（KEY_P）：蓄力 < 1/3 下网，最大只到发球线；
- 高远（KEY_GY）：最近到中线，最远到底线；
- 杀球（KEY_D）：高点击球走直线，蓄力 > 4/5 下网；蓄力越小落点越远（最远到中线）；不满足直线条件则转平抽；
- 平抽出界阈值随击球点变化：网前 > 1/4 出界、后场 > 3/4 出界；
- 最后用一个 3D 网页展示：球场 + 网 + 按键 + 击球点 + 蓄力滑块 + 顶视/侧视切换。

**用户明确指示（原话）**：「例如蓄力 1/3 下网之类边界数据可能会产生矛盾，不用严格遵循这些边界数据，实测比较接近就行」
→ 所以本文所有边界值（1/3、4/5、1/4、3/4）是**设计目标**而不是硬约束，验收标准是「体感与视觉合理、曲线连续、波动小」。

### 2.3 弹道基元（四个积木）

所有曲线都由下面四个基元拼出来，`charge` 只负责**选基元 + 定落点/弧顶目标**。

**① 弹道积分 `integrate` / `fly_to`（RK4）**

    加速度  a = -K·|v|·v + (0, -G)
    积分    RK4，dt = 0.002 s
    fly_to(vx0, vy0, dist) -> (y_at, t_at, apex, t_apex)

**② 固定仰角二分初速 `solve_by_angle(dist, dy, angle)`**

给定仰角，用二分找初速使轨迹刚好经过水平距离 `dist`、竖直差 `dy` 的点。二分区間 `VEL_MIN=20 ~ VEL_MAX=8000`，48 次或 `hi-lo<0.5` 停。

**③ 反选仰角 `_angle_for_apex`**

要让弧顶到指定高度，就二分**仰角**（不是速度）。容差必须收到 **0.02°**——早期用 0.5° 时弧顶高度量化误差会传导成 ±0.07 s 的飞行时长抖动。

**④ 抬角过网 `_clear_angle`**

若轨迹在网面处的高度不够（`< NET_H + CLEAR_MARGIN`），从当前仰角起往上找**最小可过网仰角**。实现要点：先按自适应步长粗搜到能过网，再二分收敛到 0.02°。

    步长  step = max(ANGLE_STEP, (ANGLE_CEIL - ang0) / ANGLE_MAX_RAISE)
          ANGLE_STEP = 2°, ANGLE_CEIL = 87°, ANGLE_MAX_RAISE = 40

> 为什么必须用二分而不是「每次抬 2°」：台阶会让仰角随蓄力值呈阶梯变化，实测 0.002 蓄力步长下飞行时长跳 0.08 s，曲线簇看着一顿一顿的。

### 2.4 三个键的规则详解

#### 小球 KEY_P

    charge < 1/3   → 下网支线 netFault()
                     撞网高度 70 → 147 cm 线性升高
                     速度      320 → 900 cm/s
    撞网之后       竖直自由落体，z 微微退到 -10 cm（读作「掉回自己场地」）

    charge ≥ 1/3   → 过网吊球 lofted()
                     落点 z: 55 → 198 cm（发球线）
                     弧顶目标: 185 → 205 cm，再夹到 max(目标, 击球点y + 20)
                     过网不够时用 _clear_angle 抬仰角

下网支线**不能**用「带阻力积分 + 二分倍率」实现：那样会把速度放大到 12000+ cm/s 的非物理值。改用无阻力解析抛物线，速度完全可控：

    t_net = d_net / speed
    vy0   = (cross_y - y0 + 0.5·G·t_net²) / t_net

#### 高远 KEY_GY

    charge 0 → 1
      落点 z: 335（中线）→ 670（底线）
      弧顶:   620 → 660 cm
      过网高度自然达到 551 → 660 cm（不需要额外抬角）

#### 杀球 KEY_D

先判「高点击球且深度够」：

    straight_ok = (y0 >= SMASH_MIN_H=240) and (|z_hit| <= smash_reach_limit(y0))
    smash_reach_limit(y0) = SMASH_LAND_MAX · (y0 - NET_H) / NET_H
                          = 335 · (y0-150)/150

这个式子的来历：直线从 (y0, z_hit) 打到 (0, z_land)，要保证球在网面 z=0 处刚好 150 cm，反解出 z_hit 的最大值。

**直线分支**（条件满足时）：

    charge ≤ 4/5   → smash_straight，三维等速直线，速度 3400 cm/s
                     charge 0 落中线 335
                     向 4/5 收敛到「擦网落点」 z_graze = NET_H·|z_hit| / (y0 - NET_H)
    charge > 4/5   → smash_net，下网
                     预造 13 档下网曲线池（撞网高度 148→60，速度 2600→1612）
                     按归一化时间 [0,1] 线性互插，保证 c=0.80 → 1.00 连续

**转平抽分支**（高度不够或深度超限时）：

    charge 与落点：
      c ≤ c_out  → 落点 z 从 150 线性到 670（底线），全界内
      c > c_out  → 落点 z 继续外推到 800（出界）
    c_out = driveOutCharge(z_hit) = lerp(0.25, 0.75, clamp01((|z|-240)/(500-240)))
    形态：闭式最小仰角 → 抬角保过网 → 若初速 > 2600 则二分抬仰角降速

闭式最小仰角（无阻力近似）的推导：令 D = 水平总距、dn = 网距、q = dn/D、t = tanθ

    y_net = y0·(1 - q²) + t·(dn - dn²/D)
    令 y_net = need_y  →  t = (need_y - y0·(1-q²)) / (dn - dn²/D)
    θ = atan(t)

有阻力时实际过网会比这个低，所以随后再用 `_clear_angle` 按实测抬角。

## 3. 3D 演示网页 `curve_viewer.html`

### 3.1 技术选型：为什么是手写 WebGL

本机**没有外网**（unpkg / jsdelivr 拉 three.js 都报「基础连接已经关闭: 接收时发生错误」），所以不能用 CDN 版 three.js。于是用原生 WebGL1 手写了一套最小渲染管线：

- 4×4 矩阵库：`mat4()` / `persp(out,fovy,aspect,near,far)` / `lookAt(out,eye,ctr,up)` / `mul4(out,a,b)`，**列主序**，与 GLSL 一致；
- 一个极简着色器对：`attribute vec3 aPos; attribute vec4 aCol; uniform mat4 uMVP; uniform float uPointSize;`；
- `makeItem(mode,data,pointSize)` 建 VBO（每顶点 stride = 7 个 float = 3 pos + 4 col），`drawItem(it,mvp)` 绘制；
- `pushLine(arr,a,b,col)` 往数组里塞一条线段；全部几何都是**线段**，靠颜色区分层级。

整页零依赖：`<script src="charge_math.js">` 加载算法，再一个内联 IIFE 做渲染。双击 HTML 即可打开（`file://` 也能跑）。

### 3.5 怎么打开、怎么看

双击 `curve_viewer.html` 即可（`charge_math.js` 必须同目录，`file://` 协议下也能跑）。打开后：

1. 左侧面板默认是 **小球 P / 网前 / 蓄力 0.55**，画面里有一条明亮的青绿曲线 + 21 条暗一点的曲线族；
2. 拖**蓄力值**滑块：曲线会沿曲线族平滑滑动，到 1/3 附近从红色（下网）变成青绿（界内）；
3. 点 **杀球/平抽 D**：击球点自动跳到中场，曲线变成一条几乎笔直的绿线砸向中线附近；蓄力拉到 0.85 以上变红色撞网；

5. 按 **V** 循环 透视 → 顶视 → 侧视。顶视最适合看落点与左右（用横向瞄点滑块可以打边线），侧视最适合看弧线高度与过网；
6. **拖击球点的三个滑块**（位置 X 横向 / 位置 Y 纵深 / 高度 H）：曲线会立刻跟着换起点重算，标签从「网前」变成「自由」。比如把高度拉到 380 cm 再点 GY，就是超高位击球的高远；把纵深拉到 −60 再点 P，就是贴着网的小球。极端位置也会被夹到合法区间，不会崩。
7. 空格暂停/继续飞行动画。小球是十字标记，拖着一条到地面的虚线，方便看清它在三维里的位置。

## 4. 校验体系

全部校验都是**可重复执行**的脚本，不依赖人眼：

    python charge_curves.py    # ① Python 自检 + 导出 JSON
    node   validate_math.js    # ② JS ↔ Python 对齐 + 连续性 + 设计目标
    node   smoke_dom.js        # ③ 网页脚本真跑（DOM/WebGL stub）
    node   render_preview.js   # ④ 离屏渲染 9 张 PNG
    node   contact_sheet.js    # ⑤ 拼总览图

### 4.1 ① Python 自检 `validate()`

对 3 键 × 3 击球点 × 21 蓄力 = **189 条曲线**逐条校验：

- 不变量：点数/时间列等长、`t[0]==0`、时间列严格递增、`T > 0.05s`、不穿地（`y ≥ -1`）、末点落地（`|y| < 1e-6`）、点数 ≤ 400；
- 小球：`charge < 1/3` 必须下网、`≥ 1/3` 必须界内、落点单调变远、满蓄力 = 198（发球线）；
- 高远：c=0 到 335、c=1 到 670、全界内、落点单调变远；
- 杀球：中场全部走直线分支、c=0 到 335、`c > 4/5` 下网、点列共线；
- 平抽：网前阈值 0.25、后场阈值 0.75、阈值下界内/阈值上出界、落点单调、初速 > 240；
- **回归断言**（对应 §7.5 / §7.6 的两个 bug）：中场/后场小球 `c ≥ 1/3` 必须 `kind=drop`、`status=in`、`netY ≥ 160`、`apex ≥ 击球点y + 15`；
- 横向瞄点：瞄到 x=400（单打边线外）应判出界。

### 4.2 ② JS ↔ Python 对齐 `validate_math.js`

三段：

1. **逐条对比** 189 条：`kind`/`status` 严格相等；`dropZ` 容差 1cm 或 1%；`T` 0.01s 或 2%；`apex`/`netY` 2cm 或 2%；`speed` 5 或 2%；另查时间列严格递增/首点0/`y≥-1`。
2. **细步长连续性**：`charge` 取 0..1 共 **501 点**，同一 `kind` 的相邻落点跳变 > 12cm 或时长跳变 > 0.05s 就报错；`kind` 切换只允许发生在已知边界（1/3、4/5）。
3. **设计目标抽查**：小球 <1/3 下网、≥0.4 界内、满蓄力≈198；高远 0→335、1→670；杀球中场 c=0 直线落 335、`c ≥ 0.82` 下网；平抽 front 阈值 0.25±0.06、back 0.75±0.06。

### 4.3 ③ 网页冒烟 `smoke_dom.js`

本机**无法启动浏览器**（见 §8），所以用最小 stub 在 node 里**真正执行** `curve_viewer.html` 的内联脚本：

- 正则取出唯一无 `src` 的 `<script>` 块，`vm.runInContext` 执行；
- `El` 类桩：`classList` 用 Set、`addEventListener`/`dispatchEvent`/`closest`/`setAttribute`/`getAttribute`，`byId` 缓存 27 个面板节点（含 `hitX`/`hitZ`/`hitH` 三个滑块与 `lb-hx`/`lb-hz`/`lb-hh` 三个数值标签，**新增 id 必须同步加进这个数组**，否则漏测）；
- WebGL 桩覆盖 `createShader`/`compileShader`/`createProgram`/`createBuffer`/`bufferData`/`drawArrays` 等，并计数 `drawCalls`/`buffersMade`/`attrPointers`；
- `window` 桩含 `devicePixelRatio=2`、`CURVE=require('./charge_math.js')`、`requestAnimationFrame` 入队。

断言：内联脚本可解析可执行、跑满 30 帧、无 NaN/undefined 读数；然后遍历 **3 键 × 3 击球点 × 3 视图 × 5 蓄力值 × 3 瞄点 × 两个开关**，检查交互无异常。

另有**击球点滑块专项断言**：拖到 4 个位置（含两个极端角 `(-260,-660,60)` 与 `(300,-45,390)`），每处校验

- `rd-hit` 读数字面量等于 `"x, z, h cm"`；
- `rd-land` 与 `rd-time` 都是有限值且 `T > 0`（拖到极端位置也不能算出 NaN）；
- 拖离预设后标签必须变「自由」，拖回 `(0,-110,168)` 必须变回「网前」。

> 坑：DOM stub 的 `dispatchEvent` 必须沿 `_parent` 冒泡，否则网页用的**行级事件委托**全部静默失效，测试会假阳性（详见 §7.11）。

## 5. API 用法

### 5.1 Python

```python
import charge_curves as cc

# 单个曲线
hit = cc.preset_hit('front')            # (0, 168, -110)
cur = cc.build_shot('P', hit, 0.55)     # 键, 击球点, 蓄力, 横瞄(默认0)
cur['kind']      # 'drop' / 'drop_net' / 'clear' / 'smash_straight' /
                 # 'smash_net' / 'drive'
cur['status']    # 'in' / 'net' / 'out'
cur['drop']      # (x, y, z) 落点，y 恒 0
cur['points']    # [(x,y,z), ...] 点列
cur['times']     # [t0, t1, ...] 与 points 等长，t0=0
cur['T']         # 总时长（秒）
cur['apex']      # 最高点 y
cur['netY']      # 网面 z=0 处的高度；未过网面时 None
cur['speed']     # 出球速度
cur['forced_net'] # 是否强制下网（JS 侧同名字段叫 forcedNet）

# 整簇（21 条）
fam = cc.build_family('GY', cc.preset_hit('back'))

# 只关心落点可以用更轻的封装
cc.drive_out_charge(-280.0)             # 出界阈值 0.25..0.75
cc.smash_reach_limit(285.0)             # 301.5
```

## 6. 纯 UI 壳 `curve_ui_only.html`

> 这一节讲另一个文件：**把 §3 那个网页里的球路逻辑全部剥掉，只留界面**。
> 需求原话：「给我不含球路逻辑代码　单ui的带注释代码」。
> 结论先说：50.5 KB / 1187 行、单文件、零依赖、双击就能开；曲线由 `setProvider(fn)` 外部注入，
> 不注入时跑内置「占位演示」假曲线。注释约 20%（232 行），每个函数上面都有一行说明它为什么存在。

### 6.1 它和 `curve_viewer.html` 到底差什么

| | `curve_viewer.html` | `curve_ui_only.html` |
|---|---|---|
| 体积 | 34.8 KB / 881 行 | **50.5 KB / 1187 行**（注释占大头） |

### 6.2 保留了什么

全部在文件内，共 12 节，每节一个横幅大注释：

1. **常量** —— 只有场地尺寸与颜色，**没有一个球路参数**：`COURT{NET_H:150, HALF_L:260, HALF_W:670, DUAL:305, SHORT_SERVICE:198, DBL_LONG_SERVICE:594}`、`COL{in, net, out}`、`KEY_LABEL`/`HIT_LABEL`/`VIEW_LABEL`/`KIND_NAME`/`STATUS_NAME`、`HIT_PRESETS`、`DEFAULT_PRESET`。
2. **矩阵工具** —— `mat4` / `persp` / `lookAt` / `mul4`，列主序，和 GLSL 的 `mat4` 一致。
3. **WebGL 最小管线** —— 一个着色器程序、一种顶点格式（stride 28 字节 = 3 pos + 4 col），`compile` / `makeItem` / `drawItem` / `pushLine`。
4. **静态场景** —— `buildScene()`：地面两片三角（外圈 + 略亮的内圈）、全部场地线（单打 ±260 / 双打 ±305 / 底线 ±670 / 前发球线 ±198 / 双打后发球线 ±594 / 中线）、地面网格（±600 与 ±700 各每 100 一条）、球网（立柱 ±305、上框 y=150、网底 y=0.5、竖线每 25、横线每 12）。
5. **三套相机** —— 与 §3.4 **逐行一致**：透视 `yaw=-0.50 pitch=0.58 dist=1900 fov=42° target=[0,150,10]`；顶视 `eye=[0,4200,0.001] up=[-1,0,0] fov=16°`；侧视 `eye=[-2050,380,0] ctr=[0,210,0] fov=30°`。
6. **球路数据接口**（下一小节细讲）。
7. **界面状态 + 击球点** —— `state{key, preset, hit:[x,y,z], charge:0.55, aimX, showFamily, playing, playT, speed:1}`，`hitPoint()` 直接返回 `state.hit`。
8. **绘制数据** —— `curveToLines`、动态批次、曲线簇常驻 VBO、`buildBall`（按时间列二分插值）。
9. **读数面板** —— `fmt(v, digits, unit)` 遇非有限值一律显示 `-`，绝不把 `NaN`/`undefined` 摆到用户脸上。
10. **交互绑定** —— 行级事件委托、预设、三视图、蓄力、瞄点、两个开关、鼠标拖动旋转 + 滚轮缩放、键盘 `1/2/3`/`V`/`Space`。
11. **重建调度 + 主循环** —— `scheduleRebuild` / `flushRebuild`（拖动时限流 ~22fps）、`resize`、`frame`。
12. **对外接口** —— `window.CurveUI`。

### 6.3 唯一接缝：`setProvider(fn)`

```js
// 不注入 = 占位模式，双击就能看
// 注入 = 用自己的算法：
window.CurveUI.setProvider(function (req) {
  // req.key    'P' | 'D' | 'GY'
  // req.hit    [x, y, z]  击球点（y 是高度，z 是纵深，cm）
  // req.charge 0 ~ 1
  // req.aimX   横向瞄点（cm）
  return {
    points: [[x,y,z], ...],   // 点列，第一个点必须是击球点
    times:  [t0, t1, ...],    // 与 points 等长，t0=0，严格递增（秒）
    T: 1.2,                   // 总时长（秒）
    drop: [x, 0, z],          // 落点
    status: 'in',             // 'in' | 'net' | 'out' → 决定颜色与徽章
    // 可选，没有就显示 "-"
    kind: 'drop', netY: 168, apex: 192, speed: 240
  };
});
```

规矩：

- 返回 `null` 或抛异常 → 该帧退回占位曲线，界面不崩；**同一个 provider 连续抛异常只警告一次**（`warnedProviderErr`），否则曲线簇每帧 21 条会把控制台刷爆。
- 返回结构不合法（`points` 不足 2 点，或 `times.length !== points.length`）也退回占位。
- `setProvider(null)` 退回占位模式；`setProvider` 会顺手 `famSig = null; famReset()` —— 曲线簇缓存的签名里不含 provider，不清就会继续画旧数据源算的 21 条。
- 面板「数据源」会显示当前状态：`占位演示` / `外部注入`。

**接真实逻辑只要三行**（`charge_math.js` 就是现成 provider）：

```html
<script src="charge_math.js"></script>
<script>
  window.CurveUI.setProvider(function (req) {
    return window.CURVE.buildShot(req.key, req.hit, req.charge, req.aimX);
  });
</script>
```

`buildShot` 返回的字段（`kind / points / times / T / drop / start / angle / speed / apex / netY / forcedNet / charge / key / status`）是**超集**，多余的字段 UI 直接忽略。

### 6.4 占位演示数据是什么

`placeholderCurve(req)` 只是让界面在没接逻辑时也能转起来，**不含任何物理**：

    落点    landZ = near + (far - near) * charge      GY: 335→670   D: 55→335   P: 55→198
    时长    T = 0.7 + 1.9 * |landZ - hitZ| / 1200
    拱高    bulge = 380 (GY) / 60 (D) / 150 (P)
    高度    y = hitY * (1 - u) + bulge * 4u(1-u)      末点强制 y = 0
    状态    charge < 0.12 → 'net'；|landX| > 260 → 'out'；否则 'in'

注释里明写了「不是球路逻辑、不含物理、仅用于确认界面能跑通」，避免被误当成算法参考。

### 6.5 保留了原来的两个性能设计

这两条是 §7.12 / §7.13 的结论，剥逻辑时**必须保留**，否则拖滑块照样卡：

1. **曲线簇与主曲线解耦**：签名 `famSigOf(hit) = key + '|' + hit.join(',') + '|' + aimX`，只跟键/击球点/瞄点有关，**与蓄力无关** —— 拖蓄力滑块完全不碰曲线簇。
2. **常驻 VBO + 分帧渐进**：`famBuf` 建一次不再删，`pumpFamily()` 每帧按 **6ms 预算**补算，算几条画几条；`dragHitBusy` 时直接冻结已算的那片，不清空不闪；`flushRebuild()` 在拖动时限流到 **45ms ≈ 22fps**。

## 7. 关键算法决策与踩过的坑

这一节是全部调试过程的沉淀，每条都对应一个真实 bug 或一次真实失败。

### 7.1 抬角过网必须二分，不能用台阶

早期用「每次抬 2°」把过网高度顶上去。结果仰角随蓄力值呈**阶梯**变化，实测 0.002 蓄力步长下飞行时长跳 0.08 s，曲线簇一顿一顿。改成 `_clear_angle`（自适应步长粗搜 + 二分收敛到 0.02°）后连续。

### 7.2 弧顶二分容差要 0.02°，不是 0.5°

0.5° 的弧顶高度量化误差会沿「弧顶 → 仰角 → 初速 → 时长」链条放大成 ±0.07 s 的时长抖动。把迭代从 22 次提到 40 次、容差收到 0.02° 才稳。

### 7.3 下网球用无阻力解析抛物线

早期用「带阻力积分 + 速度倍率二分」去命中撞网高度，二分会把速度放大到 **12000 cm/s 以上**的非物理值。改用闭式解 `vy0=(cross_y-y0+0.5·G·t²)/t` 后速度/角度完全可控。

### 7.4 平抽限速也要二分仰角

平抽初速超过 2600 就要降速，而降速的办法是**抬仰角**。如果按 2° 台阶抬，落点和时长会跳（实测 c=0.90/0.95 时 T 从 0.327 跳到 0.520）。改成在 `[ang, ANGLE_CEIL]` 上二分出刚好不超速的仰角。

### 7.5 BUG：抬角粗搜范围不足，后场小球 c=1/3 直接判下网

**现象**：后场小球在 `charge = 1/3` 处输出 `netY=137`（下网），`charge=1` 时 `netY` 只有 162（擦网）。

**根因**：`_clear_angle` 原来固定「2° × 40 次」粗搜，最多抬高 80°。但后场吊球时 `_angle_for_apex` 给出的**起始仰角是 −22°**（落点 55 cm 比击球点 600 cm 近太多，弧顶目标 185 又低于击球点 268，二分退化到 `ANGLE_FLOOR`）。40 × 2° 只抬到 58°，而这条线要 **64°** 才能过网 → 函数误判「抬到顶也过不了网」，于是输出下网。

**修法**：

    step = max(ANGLE_STEP, (ANGLE_CEIL - ang0) / max_raise)
    for _ in range(max_raise + 1): hi = min(ANGLE_CEIL, hi + step); ...

保证粗搜一定覆盖 `[ang0, ANGLE_CEIL]` 整段。

### 7.6 BUG：弧顶目标没夹到击球点之上，整条弧退化成平射

**现象**：后场 y=268、中场 y=285 配 `apex_target=185` 时，`_angle_for_apex` 的二分解退化，**弧顶恒等于击球点高度**，整条弧是平的，过网全靠后面抬角。

**修法**：`_lofted` 开头加

    apex_target = max(apex_target, hit_y + MIN_APEX_LIFT)     # MIN_APEX_LIFT = 20

修后中场小球 c=0.75/0.80/1.00 的 apex 从 285 变成 305，过网高度 162 → 209 → 239，恢复正常弧线。

两个 bug（6.5/6.6）都写成了**回归断言**，并做了反证：把修复回滚到临时副本后，`back c=0.34` 立刻报 `netY=141`。

### 7.7 直线杀的可达深度与「中场只能走直线」

    smash_reach_limit(y0) = 335·(y0-150)/150

中场 (0,285,-280) 网距 280 cm，而闭式最小角要求 `dn < D`（网必须在落点之前），当落点 z 大于击球深度时无解——球已经过网了。所以**中场杀球只能走直线分支**，这次是几何决定的，不是参数调的。

### 7.8 下网杀球要预造曲线池互插

`charge` 从 0.80 到 1.00 要平滑过渡到「撞网高度 148→60、速度 2600→1612」。直接按 charge 现算 `_net_fault` 会因为速度/角度变化导致时间列非线性，段间跳变。做法：预造 **13 档**下网曲线，各自按归一化时间 `[0,1]` 重采样到 64 点，查询时在相邻两档之间线性互插。

### 7.9 抬角二分 vs 台阶的反证

`_clear_angle` 二分前，`JUMPT` 类检查在 P/back 报 max=0.076 s、GY/front 报 max=0.087 s 的时长跳变。改二分后归零。这是当初第一次发现「台阶」问题的量化证据。

### 7.10 网页切键要跟随击球点

网页原来切到 D（杀球）还停在网前 (0,168,-110)，而网前的击球高度 168 < 240 不满足直线条件，直接变成出界平抽，看着像坏了。加 `syncHitButtons()`：切键时 `state.preset = DEFAULT_PRESET[key]`，按钮高亮同步。

**但加了击球点滑块之后这条规则要收窄**：只有击球点还处在「预设态」时才跟随默认值；一旦是「自由」（用户拖过滑块），切键只换曲线族、**保留用户摆的击球点**。否则用户把击球点拖到左后场 380cm 高位，手一抖点了别的键，位置就被重置了。

### 7.11 冒烟测试的事件冒泡假阳性

网页用**行级事件委托**（`row.addEventListener('click', e => e.target.closest('.btn'))`）。DOM stub 的 `dispatchEvent` 只在按钮自身触发、不冒泡，行监听器永远收不到 → 所有点击交互在测试里静默失效，测试却显示「interaction OK」。

修法：`dispatchEvent` 里沿 `_parent` 链向上冒泡（最多 20 层，`e.bubbles` 控制）。另外 stub 的 `textContent` 是普通属性，不能用它验证 UI 文案，改为断言 `lb-hit` 在 fire 之后的实际值。

### 7.12 曲线簇必须常驻 + 分帧渐进，否则拖滑块卡死

**现象**：把击球点做成三个滑块后，拖动时画面一顿一顿。

**实测成本**（node v24，同一台机器）：

    buildShot 单条   GY 13.3ms   P 9.2ms   D 0.01ms（中场走直线分支）
    buildFamily n=21 GY 249ms    P 87ms    D 0.2~30ms
    n=7 仍要 83ms

原来 `buildCurveVertices()` **每次重建都把 21 条曲线簇一起算**。拖蓄力滑块时这不明显（单条最贵 13ms），但拖击球点滑块时每一个 input 事件都要 250ms —— 手一拖就死。

**改法（三件事一起做才算解决）**：

1. **曲线簇与主曲线解耦**。曲线簇只跟 `(键, 击球点, 横向瞄点)` 有关，跟蓄力值无关。于是给它一个签名 `famSigOf(hit) = key|hit[0],hit[1],hit[2]|aimX`，只有签名变化才作废重算；**拖蓄力滑块完全不碰曲线簇**。
2. **常驻 VBO + 分帧渐进**。曲线簇的顶点缓冲 `famBuf` 建一次就不再 `deleteBuffer`；`pumpFamily()` 每帧只算到 **6ms 预算**用完为止，算几条画几条，20 帧左右铺满 21 条。这样即使冷启动遇到 250ms 的总量，也是摊到 40 帧里，不会一次性冻住。
3. **拖动期间冻结曲线簇 + 限流重建主曲线**。`dragHitBusy` 期间 `pumpFamily()` 直接 return，已经算好的那一片**冻在原地**继续显示（不清空，视觉上不闪），主曲线和标记照常跟手；`flushRebuild()` 限流到约 22fps（45ms），因为单条主曲线 9~23ms，逐帧算会掉帧。

另外滑块 `input` 事件在拖动时一帧能来好几个，必须用 rAF 合并成每帧一次重建（`scheduleRebuild()` + `flushRebuild()`），否则一次拖动几十个事件就是几十次重算。

> 副作用：松手后曲线簇会从上一处击球点「跳」到新击球点。因为用了冻结而不是清空，观感是「簇重新铺开」而不是「闪一下消失」，可接受。

### 7.13 界面：面板要能滚动

击球点从 3 个按钮变成 3 个滑块后，左侧面板高度涨到约 700px。1024×768 这类小窗口下面板会顶到屏幕外，最下面的读数与状态徽章看不见。

修法：`#panel` 加 `max-height: calc(100vh - 36px); overflow-y: auto;`，并给 WebKit 补一条 `::-webkit-scrollbar` 细滚动条样式（Firefox 用 `scrollbar-width: thin`）。

### 8.1 沙箱完全禁止启动浏览器

Chrome（`C:\Program Files\Google\Chrome\Application\chrome.exe`）与 Edge（`C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`）**全部启动失败**：

    [ERROR:crashpad_client_win.cc:431] OpenProcess: 拒绝访问。 (0x5)
    [FATAL:platform_channel.cc:112] Check failed: . : 拒绝访问。 (0x5)
    crash server failed to launch, self-terminating    exit code -36863
    Start-Process : Access is denied（Win32Exception）

试过全失败：`--headless=new`、`--headless=old`、`--single-process`、`--no-sandbox`、`--disable-gpu`、`--enable-unsafe-swiftshader`、独立 `--user-data-dir`、Edge、`Start-Process` 分离启动。

**根因**：沙箱禁止创建命名管道，而 Chromium 的 mojo IPC 就靠它。这是硬边界，**不要再尝试**。

→ 所以视觉校验改用自写软件光栅化器 `render_preview.js`，交互校验改用 `smoke_dom.js` 的 DOM/WebGL stub。

### 8.2 WebGL 的 lineWidth 基本是假的

多数实现把 `gl.lineWidth` 钳到 1。所以主曲线不能靠线宽和簇区分，只能靠**颜色与透明度**（主曲线 alpha=1.0，簇随蓄力 0.13→0.35）。

### 8.3 控制台编码

控制台是 cp936，Python 打印中文要么 `sys.stdout.reconfigure(encoding='utf-8', errors='replace')`，要么设 `$env:PYTHONIOENCODING='utf-8'`。`charge_curves.py` 的 `main()` 里已经做了 try/except 兜底。

### 8.4 PowerShell 管道会伪造退出码

`python x.py 2>&1 | Select -First N` 会因为管道提前关闭产生**假 exit 1**。判退出码要写：

```powershell
$o = python x.py 2>&1; Write-Output "EXIT=$LASTEXITCODE"; $o | Select-Object -Last 3
```

### 8.5 其它

- `read` 工具单次上限 2000 行 → 合并/截断大文件用 `node:fs`；
- 无外网（three.js CDN 拉不到），一切前端依赖必须自带；
- matplotlib 缺中文字体 → `curves.png` 里中文 legend 是方框，属正常；
- node v24.15.0 可用，无本地 three 包。

### 9.3 反编译坑（照抄会崩）

### 9.5 `g_CurveData` 那张大表不能用弹道复原

它是 `{高度: {角度: [{'s':累计时间, 'v':累计格数}]}}`，26 个高度档 × 角度档，最大 159 帧，射程大量封顶在 15.00 m。

试着用「配置 `angle` 当发射仰角 + 二次阻力弹道」去全局拟合（未知量 k、g，取 9 组未触顶样本），最优 RMS 相对时长误差仍有 **183%**，最优点落在 `g=2500 cm/s²、k≈0`——物理上不成立。

**结论**：它是原生侧**手工标定的距离—时间参考剖面**，不是弹道积分结果。所以 `fls_curve.py` 只把它当只读参考层 `TimeProfile`，不拿它反推轨迹。

### 10.2 六种形状的构造方式（代码里 `[F]` = 照原文复刻，`[I]` = 物理推断）

| 形状 | 构造 |
|---|---|
| 常规 / 旋转 / 假动作 / DOWN `[I]` | 固定仰角 + 二次阻力弹道 `a = -k·|v|·v + (0,-g)`；`k=airFriction/1000`、`g=|gravity|·100`；二分初速命中落点；`crossNetFix` 时每步抬 4° 直到过网高度 ≥ 网高 + fixAmplitude |
| 抛物线下压 `[I]` | 弦线 + 抛物拱 `y(u) = drop_y + y0·(1-u) + bulge·4u(1-u)`，`bulge = A·(D/100)²·100 cm`，`T = D/velocity`。依据：`parabolaMinA/MaxA` 量纲 1/m 正是 x² 系数 |
| 旋转球 `[I]` | Beta 型平滑横拱叠在基准弹道上：`amp = L·tan(offset°)`，`peak_u = clamp(1-backTime/T, 0.35..0.85)`，`a_up=4·peak_u`、`b_up=4·(1-peak_u)`，`w(u)=u^a_up·(1-u)^b_up/norm`；两端 w=0 且导数 0，起落点不动、无折角 |
| 重力陨石 `[F]` | 起点强制 `(drop.x, startHeight, drop.z)`，`y(t)=H−v0·t−0.5·G·t²`，`T=(−v0+√(v0²+2GH))/G`（H=1000, v0=434, G=617 → 1.230 s） |
| 假动作 `[F]` | 真落点沿飞行方向外推 `offset·100 cm`（6000 的 3.0 → 300 cm），超半宽按比例收回；`m_BackTime` 存回拉时长，交给 `CurveDropPosHandler` 做 Lerp |
| `speedMul` `[F]` | 压缩时间轴（点列不变），对应 `m_AverageSpeedMul/10000` |
